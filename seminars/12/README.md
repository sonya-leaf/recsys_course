Будем работать с датасетом рецептов сайта «Поварёнок»
([rogozinushka/povarenok-recipes](https://huggingface.co/datasets/rogozinushka/povarenok-recipes)):
изучим данные и представим рецепты как мешок ингредиентов (Bag of Words).
Итог — прототип рекомендательной системы, которая по списку включённых и
исключённых пользователем ингредиентов подбирает подходящие рецепты, причём
сразу тремя способами, показанными side-by-side: наивной косинусной
близостью (BoW), обученной моделью EASE и их взвешенным гибридом.

## Как устроен подход

Каждый рецепт представлен как multi-hot вектор по словарю всех ингредиентов
датасета (есть ингредиент в рецепте или нет, без учёта количества). Запрос
пользователя — такой же вектор из выбранных им ингредиентов. Рецепты,
содержащие хотя бы один исключённый ингредиент, отбрасываются. 
Дальше способы ранжирования различаются:

- **Bag of Words** — рецепты ранжируются по косинусной близости multi-hot
  векторов запроса и рецепта. Простая эвристика: все совпадения ингредиентов
  равнозначны, никакого обучения на данных нет.
- **EASE** (Embarrassingly Shallow AutoEncoder, Steck, 2019) — рецепты
  трактуются как «пользователи», ингредиенты — как «айтемы», и на матрице
  «рецепт × ингредиент» обучается линейная матрица близости ингредиентов B
  (по сути — item-item CF, но на признаках контента, а не на
  пользовательских интеракциях). Оценка рецепта под запрос — билинейная форма
  через B, поэтому в топ попадают рецепты с ингредиентами, которые 
  сочетаются с запрошенными, а не только буквально совпадают с ними.
- **Гибрид** — `a · BoW + (5 − a) · EASE`, где `a` от 0 до 5 задаёт
  пользователь ползунком. Перед смешиванием оценки BoW и EASE нормализуются
  в [0, 1] (min-max), потому что их «сырые» шкалы несравнимы; иначе `a`
  просто менял бы соотношение констант, а не реальный вклад методов.
  При `a = 5` гибрид полностью совпадает с BoW, при `a = 0` — с EASE.

Это учебный прототип, а не production-система: не учитывается количество
каждого ингредиента, синонимы (например, «яйцо» и «куриное яйцо» — разные
токены) и порядок ингредиентов в рецепте. Пока пользователь не выбрал ни
одного ингредиента, приложение показывает одну и ту же случайную подборку
рецептов в обеих колонках (с учётом исключённых ингредиентов, если они заданы).

## Структура

- `src/prepare_data.py` — скачивает датасет с Hugging Face Hub, парсит колонку
  `ingredients` в кортеж ингредиентов, убирает рецепты с ингредиентами, которые
  встречаются в датасете реже 5 раз, и кэширует очищенный результат в `data/`.
- `src/recommender.py` — `BaseIngredientRecommender` с общей логикой
  (multi-hot матрица, фильтр исключений, случайная подборка) и два наследника:
  `BagOfWordsRecommender` (косинусная близость) и `EaseRecommender` (EASE);
  `BlendedRecommender` поверх них считает взвешенную комбинацию их оценок.
- `app.py` — Streamlit-приложение: строит все три рекомендателя на одной и той
  же multi-hot матрице и выводит их результаты рядом, в трёх колонках.
- `analysis.ipynb` — аналитика по датасету: распределение числа ингредиентов
  в рецепте, самые популярные ингредиенты, long tail популярности и
  co-occurrence ингредиентов.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 -m src.prepare_data
streamlit run app.py
```

Данные кэшируются в `data/` — интернет понадобится
только при первом запуске, дальше приложение работает с локальным кэшем.
